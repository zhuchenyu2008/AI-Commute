# 行程分享功能设计

## 目标

为已登录用户提供行程分享能力：用户可以为自己的一条行程创建公开只读链接、复制链接、生成带二维码的分享图片，并随时关闭公开分享。

公开页面不要求登录，但只展示行程所需的最小信息。分享图片中的二维码指向同一个公开只读链接。

## 已确认的产品要求

- 分享方式为公开只读链接，获得链接的人无需登录。
- 行程所有者可以关闭分享；关闭后原链接和图片中的二维码立即失效。
- 分享图片优先接近 `1:1`，根据内容向下扩展，但最长不超过 `9:16`。
- 用户提供的参考图片只用于二维码区域的布局关系：底部左侧为品牌和扫码提示，右侧为二维码。
- 参考图片的颜色、字体、装饰和整体视觉均不采用；分享图片继续使用 AI Commute 现有的蓝白界面风格。

## 方案比较

### 方案一：数据库公开令牌 + 浏览器端生成图片（推荐）

数据库保存每条行程当前有效的随机公开令牌。公开页面根据令牌读取最新行程数据；浏览器使用同一份展示数据生成二维码和 PNG 图片。

优点：链接可立即撤销，页面能反映行程的最新状态，分享图片与现有 React 组件容易保持一致，适合当前 Next.js 单体项目。

缺点：需要增加两项轻量前端依赖，并处理浏览器下载、剪贴板和系统分享能力差异。

### 方案二：签名链接 + 服务端图片路由

使用签名参数表达行程和有效期，并通过 `ImageResponse` 在服务端生成图片。

优点：图片可通过固定 URL 访问，不依赖用户浏览器生成。

缺点：单条链接撤销较困难；服务端图片渲染对中文字体、复杂布局和自适应高度限制较多。

### 方案三：发布行程快照

分享时复制一份行程数据，公开页面和图片都读取该快照。

优点：分享内容不会随原行程变化，历史可追溯。

缺点：数据结构和生命周期更复杂，用户修改行程后容易看到旧内容，不符合当前功能的最小范围。

采用方案一。

## 数据模型

新增 `TripShare`：

- `id`：内部主键。
- `tripId`：关联行程，并保持一条行程最多有一个分享记录。
- `token`：高熵、不可预测的 Base64URL 随机令牌，唯一索引。
- `createdAt`、`updatedAt`：创建与更新时间。
- `revokedAt`：为空时有效；关闭分享后记录撤销时间。

`Trip` 增加可选的一对一 `share` 关系，删除行程时级联删除分享记录。

公开令牌属于 bearer secret，不采用可枚举 ID。令牌长度至少为 192 bit。数据库本身已包含完整行程数据，因此本功能选择保存随机令牌以便所有者重新打开分享面板时仍可复制现有链接。

## 服务端边界

### 所有者接口

新增 `/api/trips/[tripId]/share`：

- `GET`：返回当前分享状态；仅行程所有者可访问。
- `POST`：首次调用创建分享；已撤销时轮换令牌并重新启用；有效时返回现有链接。
- `DELETE`：设置 `revokedAt`，使公开链接立即失效。

接口统一检查登录状态和 `trip.userId === currentUser.id`。不存在或不属于当前用户时返回 `404`，避免泄露行程是否存在。

### 公开读取

新增 `/share/[token]` 页面，无需登录。页面仅在令牌存在、未撤销且关联行程存在时渲染；其他情况显示“分享链接无效或已关闭”。

页面设置 `noindex, nofollow`，不展示应用主导航、用户入口和任何管理操作。

## 公开数据投影

服务端通过独立的 `getPublicTripShare()` 查询和映射函数构造公开数据，页面与分享图片共用同一类型，避免客户端接触完整 Prisma 行程对象。

允许公开：

- 行程标题、时区、目标到达时间和最终目的地名称。
- 站点名称及顺序。
- 每段路线的起终点名称、最晚出发时间和目标到达时间。
- 已选路线的名称、交通方式、路线时长、缓冲时长。
- 路线分段的方式、标题、说明和分钟数。

禁止公开：

- 用户身份、设置、邮箱和 Telegram 信息。
- 原始提示词、Agent 会话、消息和工具调用。
- 提醒任务、通知记录、复算记录和监控操作。
- 站点私人备注、内部 ID、坐标及原始第三方响应。

公开页面读取最新行程状态；已下载的分享图片是生成当时的静态内容。

## 行程详情页交互

在行程详情页标题区域增加标准分享图标按钮，打开移动端底部面板或桌面端居中对话框。面板包含：

- `复制公开链接`
- `生成分享图`
- 支持文件分享时显示 `分享图片`
- 已启用分享时显示 `关闭分享`

首次执行复制链接或生成分享图时自动创建公开链接。创建期间禁用重复操作并显示进度。关闭分享需要确认，成功后清除当前链接和二维码状态。

剪贴板不可用时显示可选中的链接文本；系统不支持文件分享时保留 PNG 下载入口。

## 公开只读页面

页面使用项目现有蓝白配色和排版，但不使用登录后 `AppShell`。内容包括：

- AI Commute 品牌标识和“公开只读”状态。
- 行程标题、最晚出发、目标到达和预计总时长。
- 按行程分段展示的路线时间线。
- 简短说明：“此页面仅供查看，内容可能随行程更新。”

不显示取消监控、删除、Agent 对话、提醒计划和历史返回入口。

## 分享图片

### 生成方式

在浏览器端渲染专用 `TripShareCard`，使用 `qrcode` 生成二维码数据图，使用 `html-to-image` 将卡片导出为 PNG。

逻辑宽度固定为 `540px`，以 2 倍像素导出，得到 `1080px` 宽的图片。字体加载完成后再生成，避免中文字体回退造成换行变化。

### 比例规则

- 二维码栏上方的正文区域最低为 `540 x 540`，即正文 `1:1`；二维码栏不计入正文比例，固定额外增加 `108px`。
- 正文内容增加时按实际高度向下扩展，整张图片的最小逻辑尺寸为 `540 x 648`，导出后为 `1080 x 1296`。
- 最大整图为 `540 x 960`，即导出后的 `1080 x 1920`（`9:16`）。
- 未达到最大高度前不截断标题、站点或路线文字；达到上限后只限制正文容器高度，二维码栏仍完整保留。

### 视觉结构

主体沿用项目现有常规样式：浅灰白背景、深色文字、蓝色重点信息和克制的状态色。

底部二维码区域是独立的全宽信息栏，仅采用参考图片的布局关系：

- 左侧显示 AI Commute 品牌名称或标识。
- 品牌下方显示“扫码查看完整行程”。
- 右侧显示二维码，并保留二维码规范要求的空白静区。
- 信息栏使用纯色高对比背景，约占方形图片高度的 `18%` 至 `22%`。
- 二维码区域不叠加纹理、渐变、透明效果或路线图形。

二维码编码完整公开 URL。关闭分享后，图片本身仍存在，但二维码打开的页面会显示链接已失效。

### 文件行为

- 默认文件名：`AI-Commute-<行程标题>-<北京时间日期>.png`。
- 支持 Web Share API 且允许分享文件时，用户可直接调用系统分享面板。
- 其他浏览器下载 PNG，并保留复制公开链接功能。

## 错误处理

- 创建分享失败：保留面板，显示错误并允许重试。
- 公开令牌无效或已撤销：返回统一失效页面，不区分具体原因。
- 二维码或图片生成失败：公开链接仍保持可复制，不自动撤销。
- 浏览器拒绝剪贴板或文件分享权限：回退到链接文本或 PNG 下载。
- 行程缺少已选路线：仍可分享标题、站点和时间，并显示“路线详情待完善”。

## 测试

### 单元测试

- 公开数据投影不会包含身份、坐标、备注、提醒、通知和 Agent 数据。
- 随机令牌格式与长度满足要求。
- 正文区域保持 `1:1`，二维码栏独立增加高度，整图不超过 `9:16`。
- 未达到最大高度前长标题和路线文本不会被提前截断。

### 集成测试

- 未登录用户不能创建、查询或关闭分享。
- 用户不能操作其他用户的行程分享。
- 创建分享可重复调用并返回同一有效链接。
- 撤销后公开查询失效，再次启用时轮换令牌。
- 删除行程后分享记录级联删除。

### 组件与端到端测试

- 行程详情页可以打开分享面板并完成复制、下载和关闭分享流程。
- 无登录会话可访问有效公开页面。
- 公开页面不出现私人字段和管理按钮。
- 分享图片底部保持左侧品牌与提示、右侧二维码的布局。
- 在移动端与桌面端验证弹层不溢出、不被底部导航遮挡。
- 校验导出图片宽度为 `1080px`，高度不小于 `1080px` 且不大于 `1920px`。

## 非目标

- 不提供指定用户邀请和权限协作。
- 不提供实时位置追踪。
- 不提供分享访问统计、访问密码和自动过期设置。
- 不为每次分享保留历史版本或图片副本。
- 不把提醒、监控状态或 Agent 对话公开给访问者。
